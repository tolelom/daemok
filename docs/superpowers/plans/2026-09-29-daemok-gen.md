# daemok gen 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v0.4 설계에서 Go 생성 파일을 만들고, `daemok gen`으로 쓰고 지우며, `daemok check`가 생성 파일 최신 여부를 본다.

**Architecture:** `internal/gen/golang`이 모델에서 `[]File{Path, Content}`를 만든다(디스크를 모른다). `internal/workspace`가 설계 읽기, 설계 검사, 생성, 디스크의 생성 파일 스캔을 묶어 진단 목록과 쓰기 계획을 만든다. `cmd/daemok`의 `check`와 `gen`은 workspace만 부른다. serve도 나중에 workspace를 쓴다.

**Tech Stack:** Go 표준 라이브러리(`go/format`, `io/fs`, `os/exec`는 테스트에서만)

**Spec:** `docs/superpowers/specs/2026-09-27-daemok-mvp-design.md`(생성 규칙, 생성 파일 최신 여부), `docs/superpowers/specs/2026-09-29-daemok-format-v04-design.md`(관계·이벤트·흐름의 생성), `docs/design/01-model.md`(생성 파일 표)

## Global Constraints

- 생성 파일 첫 줄은 `// Code generated by daemok. DO NOT EDIT.`다.
- 출력은 `go/format.Source`를 거친다. 같은 설계에서 같은 바이트가 나온다. 파일 순서는 경로순, 파일 안은 설계 파일 이름순·적힌 순서다.
- `gen: false` 노드는 어느 파일에도 나오지 않는다.
- 생성 파일 범위는 코드 루트 아래 첫 줄이 생성 헤더인 `.go` 파일. `.`으로 시작하는 디렉토리, `vendor`, `testdata`, `node_modules`는 보지 않는다.
- 최신 여부 비교 전에 디스크 쪽 CRLF를 LF로 바꾼다.
- 진단 메시지는 "설명: 대상" 형식.

## Review Focus

- 생성 경로에 헤더 없는 손 파일이 있을 때: `gen`은 아무것도 쓰지 않고 1, `--dry-run`도 1, `check`는 오류. Task 9·10에서 테스트한다.
- 설계에서 모듈을 지웠을 때 그 디렉토리의 생성 파일: `gen`이 지우고 `check`는 오류. Task 9에서 테스트한다.
- CRLF로 체크아웃된 생성 파일: 최신으로 본다. Task 9에서 테스트한다.
- 두 모듈이 같은 마지막 경로 요소(`a/query`, `b/query`)를 가져 import 이름이 겹칠 때: 별칭으로 컴파일된다. Task 5에서 테스트한다.
- undo가 없는 흐름, commit이 없는 흐름: 쓰지 않는 변수 없이 컴파일된다. Task 7에서 테스트한다.

## 생성 규칙

| 원본 | 파일 | 내용 |
|---|---|---|
| enum | `<모듈>/<enum id>.gen.go` | `type T string`, 상수(`go.prefix` 또는 T + 값 CamelCase), `Valid()`, `TValues()` |
| 모듈의 consts | `<모듈>/consts.gen.go` | const 블록. duration은 `N * time.Unit` |
| 모듈의 errors | `<모듈>/errors.gen.go` | sentinel var 블록, http가 있으면 `HTTPStatus(err) int`(기본 500) |
| 모듈의 types | `<모듈>/types.gen.go` | struct. `ref`는 `*T`, `many`면 `[]T`. optional은 포인터와 `omitempty` |
| 모듈의 call 계약 | `<모듈>/contracts.gen.go` | interface. 반환 끝에 `error`. 인자·반환의 설계 struct는 포인터 |
| handler_kind | `<모듈>/<id>.gen.go` | 함수 타입 |
| 그룹 멤버 | `<멤버 path>/register.gen.go` | `init()` 등록, `var _ Handler = f` |
| 실행 단위 | `cmd/<id>/modules.gen.go` | composes의 그룹 멤버 blank import |
| needs가 있는 모듈·멤버 | `<path>/needs.gen.go` | 계약마다 uses 메서드만의 interface. 멤버는 그룹 needs를 포함 |
| 실행 단위 | `cmd/<id>/contracts.gen.go` | 조립하는 받는 쪽·주는 쪽 쌍마다 `var _ 받는.I = (*구현.I)(nil)` |
| event_kind | `<모듈>/<id>.gen.go` | 이벤트마다 `<Event>Data` struct, map이면 `Map()`과 `<Event>DataFrom` |
| event_kind를 가진 모듈(map) | `<모듈>/daemok_event.gen.go` | 변환 도우미 |
| 흐름 | `<모듈>/<id>.gen.go` | `<Flow>Steps` interface, `Run<Flow>` |
| 흐름을 가진 모듈 | `<모듈>/daemok_flow.gen.go` | `FlowError`, `daemokUndo` |
| cases가 있는 함수 | `<모듈>/<id>_gen_test.go` | 테이블 테스트 |
| 그 모듈 | `<모듈>/daemok_case_gen_test.go` | `caseInput`, `errAny`, `checkErr`, `checkExpect` |

- 패키지 이름은 경로의 마지막 요소. `query` 구현 패키지는 `<주는 모듈 path>/query`.
- 타입 이름: 설계 enum·struct는 `go.type`·`go.name` 또는 ID의 GoName. 다른 모듈이면 `pkg.Name`으로 쓰고 import를 더한다.
- 외부 타입 `x.Name`: `x`가 설계 모듈·멤버 ID면 그 모듈을 import한다. `json`, `time`, `http`, `context`, `io`는 표준 라이브러리 경로로 import한다. 그 밖은 그대로 쓴다.
- import 이름이 겹치면 두 번째부터 경로 요소를 이어 붙인 별칭(`postquery`)을 쓴다.
