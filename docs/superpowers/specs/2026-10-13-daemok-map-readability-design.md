# daemok 지도 가독성

> 패키지가 많은 프로젝트를 분석 모드로 열었을 때 지도를 읽을 수 있게 합니다. 관계선, 띠, 상자 이름 규칙을 정합니다.

패키지 52개를 분석 모드로 열면 모듈 51개와 관계선 161개가 import 깊이로 센 `tier0`부터 `tier4`까지의 띠에 흩어집니다. 한 도메인의 하위 패키지(`x`, `x/query`, `x/service`)가 서로 다른 띠에 놓이고, 흐린 관계선이 지도를 덮고, 긴 이름이 상자를 넘습니다.

## 관계선

| 조건 | 처음 모습 |
|---|---|
| 대조 모드, 관계선 60개 이하 | 흐리게 보입니다 |
| 대조 모드, 관계선 60개 초과 | 숨깁니다 |
| 분석 모드 | 숨깁니다. 영역 띠는 의존 순서가 아니라서 흐린 선이 흐름을 보여 주지 못합니다 |

숨길 때는 오른쪽 칸에 "관계선은 모듈에 올렸을 때만 보인다"를 적습니다. 모듈에 올렸을 때와 "모두 보기"는 기존과 같습니다. tolchain 설계의 지도 관계선은 36개라 흐린 선을 유지합니다.

## 분석 모드 띠

분석 모드의 띠는 tier가 아니라 디렉토리 영역입니다.

| 항목 | 규칙 |
|---|---|
| 뿌리 | 하위 패키지는 경로가 가장 가까운 조상 모듈로 접고, 접은 모듈도 같은 규칙으로 다시 접습니다 |
| 담는 그릇 | 조상과 패키지 사이 디렉토리에 모듈 갈래가 둘 이상이면 조상은 담는 그릇이라 접지 않습니다. 사이 디렉토리가 `internal`이면 그 조상 전용이라 갈래를 세지 않습니다 |
| 영역 | 뿌리의 부모 디렉토리. 코드 루트면 "루트" |
| 띠 순서 | 영역 안 모듈의 tier 평균이 높은 것부터. 같으면 영역 경로 순 |
| 띠 안 순서 | 경로 순. 하위 패키지는 부모 바로 뒤에 옵니다 |
| 부제 | 영역 기준 상대 경로. 모듈 ID와 같으면 적지 않습니다 |

대조 모드는 설계의 tier로 그립니다.

## 상자와 띠 이름

| 대상 | 규칙 |
|---|---|
| 모듈 이름 | 상자 폭에 맞게 글자를 14.5px에서 12px까지 줄이고, 그래도 넘치면 가운데를 줄입니다. 마지막 `_` 뒤(`_service`, `_query`)는 구분에 쓰여서 남깁니다. 전체 이름은 툴팁 |
| 띠 이름 | `/` 뒤에서 줄을 나눠 한 줄 12자까지. 더 긴 마디는 줄입니다 |
