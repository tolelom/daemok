# daemok 지도 가독성

> 패키지가 많은 프로젝트를 분석 모드로 열었을 때 지도를 읽을 수 있게 합니다. 관계선, 올렸을 때 부제, 띠, 접기, 공용, 상자 이름 규칙을 정합니다.

패키지 52개를 분석 모드로 열면 모듈 51개와 관계선 161개가 import 깊이로 센 `tier0`부터 `tier4`까지의 띠에 흩어집니다. 한 도메인의 하위 패키지(`x`, `x/query`, `x/service`)가 서로 다른 띠에 놓이고, 흐린 관계선이 지도를 덮고, 긴 이름이 상자를 넘습니다.

## 관계선

| 조건 | 처음 모습 |
|---|---|
| 대조 모드, 관계선 60개 이하 | 흐리게 보입니다 |
| 대조 모드, 관계선 60개 초과 | 숨깁니다 |
| 분석 모드 | 숨깁니다. 영역 띠는 의존 순서가 아니라서 흐린 선이 흐름을 보여 주지 못합니다 |

숨길 때는 오른쪽 칸에 "관계선은 모듈에 올렸을 때만 보인다"를 적습니다. 모듈에 올렸을 때와 "모두 보기"는 기존과 같습니다. tolchain 설계의 지도 관계선은 36개라 흐린 선을 유지합니다.

관계선의 라벨(이벤트, 계약, 핸들러 종류 이름)은 "모두 보기"에서 모듈에 올리지 않았을 때만 보입니다. 올렸을 때는 이어진 상자 부제가 같은 라벨을 적고, 선 위 라벨은 다른 선과 겹칩니다.

### 선 모양

| 경우 | 모양 |
|---|---|
| 같은 줄, 이웃 칸 | 옆면끼리 직선 |
| 같은 줄, 건너는 칸 | 두 상자 윗면에서 줄 위 여백(22px 안)으로 넘어가는 곡선. 사이 상자를 지나지 않습니다 |
| 다른 줄, 같은 열이고 사이 상자 없음 | 아랫면·윗면 가운데끼리 직선 |
| 다른 줄, 그 밖 | 출발 줄 옆 여백 → 도착 상자 옆 열 사이 통로(출발 쪽에 가까운 쪽) → 도착 줄 옆 여백으로 꺾어 가는 선. 꼭짓점은 6px로 둥글리고, 같은 통로를 여러 선이 쓰므로 선마다 ±6px 안에서 비킵니다 |
| 같은 두 상자 사이 선이 여럿 | 방향과 종류에 관계없이 8px 간격 차선으로 벌립니다 |

## 올렸을 때 상자 부제

모듈에 올리면 보이는 관계선으로 이어진 상자의 부제를 그 상자 입장의 관계로 바꾸고, 내리면 되돌립니다.

| 관계선 종류 | 방향 | 그 상자 → 올린 모듈 | 올린 모듈 → 그 상자 |
|---|---|---|---|
| 의존, 계약, 그룹 예외 | 쓰는 쪽 → 쓰이는 쪽 | 사용 | 제공 |
| 이벤트 | 발행자 → 구독자 | 발행 | 구독 |
| 핸들러 등록 | 멤버 → 핸들러 종류의 주인 | 등록 | 등록받음 |

의존이 아닌 관계는 라벨을 두 개까지 붙이고(`구독 · tx_executed`), 계약은 종류 이름도 붙입니다(`제공 · call 계약 X`). 두 방향이 다 있으면 `/`로 잇습니다.

## 분석 모드 띠

분석 모드의 띠는 tier가 아니라 디렉토리 영역입니다.

| 항목 | 규칙 |
|---|---|
| 뿌리 | 하위 패키지는 경로가 가장 가까운 조상 모듈로 접고, 접은 모듈도 같은 규칙으로 다시 접습니다 |
| 담는 그릇 | 조상과 패키지 사이 디렉토리에 모듈 갈래가 둘 이상이면 조상은 담는 그릇이라 접지 않습니다. 사이 디렉토리가 `internal`이면 그 조상 전용이라 갈래를 세지 않습니다 |
| 영역 | 뿌리의 부모 디렉토리. 코드 루트면 "루트" |
| 띠 순서 | 영역 안 모듈의 tier 평균이 높은 것부터. 같으면 영역 경로 순 |
| 접기 | 지도는 뿌리 모듈만 그립니다. 하위 패키지가 있는 상자는 겹 상자로 그리고(뒤 상자는 테두리만 그려 그 아래를 지나는 관계선을 가리지 않습니다) 부제에 "하위 패키지 N"을 적습니다. 하위 패키지의 관계선은 뿌리로 모으고, 찾기에서 하위 패키지가 맞으면 뿌리를 강조합니다 |
| 공용 | 뿌리 모듈의 30% 이상, 그리고 최소 3개가 쓰는 뿌리는 영역에서 빼 마지막 "공용" 띠에 둡니다. 점선 상자로 흐리게 그리고, 이 모듈로 가는 관계선은 이 모듈에 올렸을 때만 보입니다 |
| 띠 안 순서 | 경로 순 |
| 부제 | 하위 패키지 수, 없으면 영역 기준 상대 경로. 모듈 ID와 같으면 적지 않습니다 |

공용 기준은 네 프로젝트를 분석 모드로 열어 정했습니다. 접은 뒤 상자 29개인 프로젝트에서 30% 이상은 계약·설비 패키지 4개(34~45%)이고, 25%로 내리면 도메인 모듈(24%)까지 빠집니다. tolchain(상자 21개)은 core, events, crypto, vm, fiber_api_server(20개)는 model, dto, daemok(15개)은 model, yaml, gosrc, golang이 공용이 됩니다.

대조 모드는 설계의 tier로 그립니다.

## 분석 모드 모듈 탭

| 자리 | 내용 |
|---|---|
| 왼쪽 목록 | 지도와 같은 영역과 공용으로 묶습니다. 하위 패키지는 뿌리 모듈 아래에 뿌리 기준 상대 경로(`query`, `internal/kafka`)로 들여 쓰고 ID는 툴팁 |
| 머리글 | tier 대신 영역 |
| 하위 패키지 | 이 모듈로 접히는 모듈 |
| 외부 의존 | 초안 메모의 외부 의존 중 이 모듈이 쓰는 것 |
| 연결 | 아래 연결 표. 뿌리 모듈은 하위 패키지까지 한 모듈로 보고, 하위 패키지를 누르면 그 패키지만 봅니다 |
| L3 후보 | 연결 표 아래 표. 초안 메모의 L3 후보 중 이 모듈과 하위 패키지의 것을 패키지·종류·이름·위치로 적습니다 |

대조 모드의 모듈 탭은 설계의 tier로 묶습니다.

### 연결 표

두 모드의 모듈 탭은 다른 모듈과의 관계를 상대·이 모듈 쪽·무엇·설명 표 하나로 적습니다.

| 항목 | 규칙 |
|---|---|
| 절 | 이 모듈 입장의 말로 나눕니다. 쓰는 것, 쓰는 쪽, 발행, 구독, 등록, 등록받음 순. 말은 지도의 올렸을 때 부제와 같습니다 |
| 줄 | 같은 절에서 상대와 이 모듈 쪽 패키지가 같으면 한 줄. 같은 상대가 이어지면 상대 이름은 첫 줄에만 적습니다. 분석 모드는 같은 뿌리의 상대를 붙여 놓습니다 |
| 이 모듈 쪽 | 하위 패키지가 있는 뿌리 모듈일 때만 있는 칸. 뿌리 기준 상대 경로이고 뿌리 자신은 비웁니다 |
| 무엇 | 분석 모드는 초안 메모의 쓰는 이름을 함수, 인터페이스, 타입, 에러, 상수, 변수 순으로 종류와 함께 적고, 8개를 넘으면 나머지는 "외 N"으로 접습니다. 대조 모드는 이벤트·계약·핸들러 종류 이름과 계약 종류입니다 |
| 설명 | 관계의 why. why가 있는 관계가 하나라도 있을 때만 칸을 둡니다 |
| 무엇이 없는 상대 | 절 끝 한 줄에 모읍니다. 분석 모드는 "이름 없이 import"를 붙입니다 |

## 분석 모드 초안 탭

| 자리 | 내용 |
|---|---|
| 개수 | 패키지, 모듈, 실행 단위, 많이 쓰이는 패키지, 건너뛴 것. 건너뛴 것은 개수를 누르면 펼칩니다 |
| 외부 의존 | 모듈·쓰는 곳 표. 쓰는 곳은 지도처럼 뿌리 모듈로 접습니다 |
| L3 노드 후보 | 패키지·종류·이름·위치 표. 지도의 영역 순서 |
| 초안 YAML | 저장 버튼과 명령 아래에 접어 둡니다 |

## 상자와 띠 이름

| 대상 | 규칙 |
|---|---|
| 모듈 이름 | 상자 폭에 맞게 글자를 14.5px에서 12px까지 줄이고, 그래도 넘치면 가운데를 줄입니다. 마지막 `_` 뒤(`_service`, `_query`)는 구분에 쓰여서 남깁니다. 전체 이름은 툴팁 |
| 띠 이름 | `/` 뒤에서 줄을 나눠 한 줄 12자까지. 더 긴 마디는 줄입니다 |
| 상자 부제 | 렌더한 폭을 재서 상자 안쪽 폭을 넘으면 끝을 줄입니다. 한글은 영문보다 넓어 글자 수로 자르지 않습니다. 올렸을 때 바뀌는 관계 부제도 같습니다 |
| 모듈 탭 왼쪽 목록 이름 | `_` 뒤에서만 줄을 나눕니다. 상태 표시(추가, 수정, 삭제)는 줄바꿈하지 않습니다 |

## 테스트

| 대상 | 확인 |
|---|---|
| e2e `mapdense.mjs` | 모든 관계선이 끝점이 아닌 상자를 지나지 않음, 같은 줄 이웃 칸 직선, 건너는 선이 사이 상자를 지나지 않고 줄 위 여백 안에 있음, 같은 두 상자 사이 선의 차선. 관계선이 많은 분석 모드에서 처음에 모두 숨김과 안내 문구, 올렸을 때 보임, 긴 이름의 가운데 줄임과 툴팁, 띠 이름이 상자에 닿지 않음, 한글 긴 부제가 상자 안에서 줄어듦, 영역 띠와 순서, 하위 패키지 접기와 관계선·찾기의 뿌리 모음, 겹 상자가 밖으로 나온 띠를 덮지 않음, 공용 띠와 공용 관계선 규칙. 모듈 탭의 영역 목록, 하위 패키지 들여쓰기와 상대 경로, 목록 이름이 잘리지 않음, 머리글의 영역, 하위 패키지·외부 의존, L3 후보 표. 연결 표의 절, 쓰는 이름과 종류, 이 모듈 쪽 패키지, 자기 하위 패키지가 상대로 나오지 않음, 이름 없이 import한 상대 한 줄. 초안 탭의 외부 의존 표(뿌리로 접음), L3 후보 표, 접힌 YAML |
| e2e `map.mjs` | 대조 모드의 흐린 관계선 유지, 올렸을 때 부제가 사용·제공으로 바뀌고 내리면 돌아옴, 종류별 관계 문구, 올렸을 때 선 라벨이 숨고 모두 보기에서 보임, 모듈 탭 연결 표의 절과 종류별 절 이름, 왼쪽 목록의 긴 이름이 `_` 뒤에서만 줄바꿈 |
| `infer` | 별칭 import와 package 절 이름으로 쓴 이름, 선언 종류, 대상 패키지에 없는 이름·`_test.go` 제외 |
| 실측 | 패키지 52개 프로젝트, tolchain, daemok 자신을 열어 모든 탭 JS 오류 0. 패키지 52개 프로젝트에서 지도 올리기, 모듈 누르기, 왼쪽 목록의 하위 패키지 누르기, 본문 링크, 초안 탭, 지도로 돌아가기를 차례로 확인 |
