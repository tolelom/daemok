# daemok 일반 함수

> L4 `funcs`에 핸들러와 계약 메서드가 아닌 일반 함수를 더합니다. 설계 에러를 반환하는 손으로 쓴 함수의 에러 계약과 케이스 표를 설계에 둡니다.

## 형태

```yaml
funcs:
  safe_add:
    in: vm
    errors: [ErrBalanceOverflow]
    cases:
      - { name: "넘침", given: { a: 18446744073709551615, b: 1 }, error: ErrBalanceOverflow }
```

| 항목 | 규칙 |
|---|---|
| 구분 | `kind`+`handles`도 `of`도 없으면 일반 함수입니다 |
| Go 이름 | `go.name`, 없으면 ID의 CamelCase. `go.name`은 일반 함수에만 씁니다 |
| 시그니처 | 적지 않습니다. 케이스 테스트는 손으로 쓰는 `run<함수>Case`를 거쳐 호출하므로 시그니처를 쓰지 않습니다 |
| 본문 | 언제나 손으로 씁니다. `gen`은 케이스 테스트를 생성할지만 정합니다 |

함수 개수로 coverage를 채우는 것은 목적이 아닙니다. tolchain의 exported 최상위 함수 73개 중 반환문에서 `Err`로 시작하는 sentinel을 쓰는 것은 3개, fiber_api_server는 52개 중 6개이고(테스트 파일과 `testutil` 제외), 나머지(생성자, 설정, 미들웨어, 변환)는 설계에 올려도 에러 계약이 없습니다.

## 검사

| 대상 | 수준 | 내용 |
|---|---|---|
| `go.name` | 오류 | 핸들러·계약 메서드에 씀, export되지 않는 이름 |
| 코드 대조 | 오류 | 소속 모듈 패키지에 Go 이름의 최상위 선언이 없음. 본문을 늘 손으로 쓰므로 `gen` 값과 관계없이 봅니다 |
| 케이스가 없는 에러 | 경고 | 기존 규칙입니다. `gen: false` 함수는 케이스 테스트를 생성하지 않으므로 보지 않습니다 |

coverage는 일반 함수를 Go 이름으로 셉니다.

## L3 초안

`daemok init --l3`는 exported 최상위 함수(메서드 제외) 중 반환문에서 설계 에러를 가리키는 것을 일반 함수 노드로 옮깁니다.

- 설계 에러는 기존 설계의 에러와 같은 초안에서 옮기는 에러입니다. 같은 패키지의 이름이나, 설계 모듈 패키지를 한정한 이름(`core.ErrX`)으로 가리킨 것을 셉니다. `fmt.Errorf("%w", ErrX)`처럼 반환식 안에 들어 있어도 셉니다.
- 노드는 `{ in, gen: false, errors: [...] }`이고 `errors`는 에러 ID 순입니다. Go 이름이 ID의 CamelCase와 다르면 `go.name`을 붙입니다.
- 설계 에러를 반환하지 않는 함수는 옮기지 않고 수만 알립니다.
- YAML에서 `funcs`는 `contracts` 다음입니다.

## 테스트

| 대상 | 확인 |
|---|---|
| 읽기 | `kind`·`of` 없는 함수, 일반 함수가 아닌 곳의 `go.name` 오류 |
| 검사 | export되지 않는 `go.name`, `gen: false` 함수의 케이스 없는 에러 경고 없음 |
| 코드 대조 | 선언이 없으면 `gen`과 관계없이 오류 |
| coverage | 일반 함수의 Go 이름이 대응으로 셈 |
| 초안 | 같은 패키지·다른 모듈·`%w` 감싸기의 설계 에러, 초안 안의 에러, 설계 에러가 없는 함수 제외, `go.name` |
| 실측 | tolchain·fiber 사본에서 초안을 더한 설계가 `check --strict` 통과 |
