# 설계 변경 요약

> 기준 ref의 설계와 작업 폴더의 설계를 노드와 키 단위로 비교해, PR 설명에 붙일 수 있는 마크다운으로 출력합니다.

## 목적

설계 변경의 승인은 커밋입니다. 리뷰하는 사람이 YAML diff만 보면 흐름 형식 한 줄 안에서 무엇이 바뀌었는지, 노드가 옮겨졌을 뿐인지 알기 어렵습니다. 바뀐 노드와 키를 설계 파일의 키 이름 그대로 적어 리뷰 비용을 낮춥니다.

## 진입점

| 진입점 | 형태 |
|---|---|
| CLI | `daemok diff [--base REF] [--design DIR] [--root DIR]`. 기본 REF는 `HEAD`. 출력은 마크다운 |
| MCP | 읽기 전용 도구 `diff`. 인자 `base`(기본 `HEAD`), `design`, `root`. CLI와 같은 글을 줌 |

종료 코드는 0 출력함, 2 진행할 수 없음입니다. 기준 ref를 읽지 못하거나, 설계 디렉토리가 git 저장소 안이 아니거나, 어느 한쪽 설계 파일이 YAML로 읽히지 않으면 2입니다. 기준 ref에 설계 디렉토리가 없으면 모든 노드를 추가로 봅니다.

## 기준 설계 읽기

`gitbase.Files`가 ref를 받게 넓힙니다. 설계 디렉토리의 그 ref 시점 `*.yaml`을 읽습니다. 화면은 지금처럼 `HEAD`를 넘깁니다.

## 노드 맞추기

- 양쪽 설계 파일을 각각 YAML로 읽어 노드를 (종류, ID)로 모읍니다. 종류 이름은 설계 파일의 키입니다. 여러 파일에 나뉜 노드도 모으므로, 노드를 다른 파일로 옮긴 것은 변경이 아닙니다.
- 그룹 멤버는 `members` 종류로 따로 모읍니다. 그룹 노드를 비교할 때 `members` 키는 뺍니다.
- `system`의 `actors`, `interfaces`는 각각 `actors`, `interfaces` 종류로 모읍니다. `system` 노드 자체는 두 키를 뺀 나머지로 비교합니다.
- 최상위 `version`, `go_module`, `ts_out`, `tiers`는 노드가 아닌 설정으로 비교합니다.
- 비교는 YAML 값으로 합니다. 주석, 정렬, 흐름·블록 형식, 따옴표 유무는 변경이 아닙니다.

## 값 비교

키 경로(`fields.title`, `go.name`)마다 비교합니다.

| 값 | 출력 |
|---|---|
| 스칼라 | `tier: b → c` |
| 키 추가·삭제 | `fields.title 추가: string`, `path 삭제: core`. 값이 맵이나 목록이면 한 줄 흐름 형식으로 적음 |
| 스칼라 목록 | `depends_on: +core -auth`. 원소가 같고 순서만 다르면 `depends_on: 순서 바뀜` |
| 맵 목록 | 원소를 짝지을 키가 있으면 그 키로 짝지어 원소별로 비교. 흐름 `steps`는 `id`, 케이스 `cases`는 `name`. 짝이 없는 원소는 추가·삭제, 짝의 순서가 다르면 `순서 바뀜`. 짝지을 키가 없는 목록은 통째로 비교해 `값 바뀜` |

## 이름 바뀜

같은 종류에서 삭제된 노드와 추가된 노드의 값이 같으면 `이름 바뀜: a → b`로 묶습니다. 비교에서는 `daemok rename`이 더하는 고정 키(`go.name`, `go.type`, `path`)를 뺍니다. 한 삭제 노드에 짝이 둘 이상이면 묶지 않습니다. 이름 바꾸기로 참조만 바뀐 다른 노드는 수정으로 나옵니다.

## 출력

```markdown
## 설계 변경 (HEAD 대비)

### 설정
- tiers: +edge

### 추가
- 모듈 `edge`

### 이름 바뀜
- 타입 `post` → `article`

### 수정
- 모듈 `web`
  - tier: b → c
  - depends_on: +edge -auth
- 타입 `article`
  - go 추가: { name: Post }

### 삭제
- 에러 `ErrOld`
```

- 절 순서는 설정, 추가, 이름 바뀜, 수정, 삭제입니다. 빈 절은 쓰지 않습니다.
- 각 절 안에서는 설계 파일의 종류 순서, 같은 종류 안에서는 ID 순입니다.
- 종류 이름은 한국어 라벨(요구사항, 모듈, 그룹 멤버, enum 등)로 적습니다.
- 바뀐 것이 없으면 `설계 변경 없음 (HEAD 대비)` 한 줄입니다.

## 하지 않는 것

- 진단 증감 표시. `daemok check`가 합니다
- 화면의 변경 목록 바꾸기. 지금처럼 화면 JS가 노드 단위로 계산합니다
- 이름 바꾸기로 참조만 바뀐 노드 숨기기

## 테스트

| 대상 | 확인 |
|---|---|
| 노드 맞추기 | 노드를 다른 파일로 옮기거나 흐름·블록 형식, 주석, 따옴표만 바꾸면 변경 없음 |
| 값 비교 | 스칼라, 키 추가·삭제, 스칼라 목록 추가·삭제·순서, steps의 단계 끼워 넣기(뒤 단계는 바뀌지 않음), 짝지을 키 없는 맵 목록 |
| 멤버·system | 멤버 변경은 멤버로, 그룹의 다른 키 변경은 그룹으로 나옴. actors·interfaces도 같음 |
| 이름 바뀜 | `daemok rename` 기본 모드 결과가 이름 바뀜 한 건과 참조 노드 수정으로 나옴. 내용이 다른 삭제·추가는 묶지 않음 |
| 기준 읽기 | 임시 git 저장소에서 `--base`로 이전 커밋과 비교, 없는 ref는 2, 기준에 설계가 없으면 모두 추가 |
| 진입점 | CLI 출력과 종료 코드, MCP `diff` 도구 결과 |
