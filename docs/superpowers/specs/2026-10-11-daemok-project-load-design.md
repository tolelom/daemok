# 프로젝트 열기와 코드 분석

> 문제와 원칙은 [개요](../../design/00-overview.md)에, 명령과 구조는 [MVP 설계](2026-09-27-daemok-mvp-design.md)에 있습니다. 이 문서는 `daemok serve` 화면에서 프로젝트를 열고, 설계 파일이 없는 Go 프로젝트는 코드에서 L2 초안을 만드는 기능을 정합니다. MVP에서 제외한 "코드에서 설계 추출"은 개요의 원칙 2에 따라 기존 프로젝트를 처음 가져올 때만 씁니다.

## 완료 조건

1. `go test ./...` 통과.
2. tolchain `main` `29c1d3a`의 임시 복사본에서 `daemok init` 실행 후 `daemok check`의 오류 0.
3. 2의 초안과 [tolchain 슬라이스](../../design/02-slice-tolchain.md)의 손으로 쓴 설계 파일을 비교해 슬라이스 문서에 기록합니다. 세는 대상은 tier 배치를 바꿔야 하는 모듈, 그룹으로 묶어야 하는 패키지, ID를 바꿔야 하는 모듈입니다.
4. 인자 없는 `daemok serve`에서 프로젝트 열기 패널, 경로 입력, 분석 모드, 초안 저장, 대조 모드 전환이 이어집니다.
5. tolchain과 fiber_api_server의 임시 복사본, 패키지 60개짜리 합성 fixture에서 분석 모드 지도를 읽을 수 있습니다.

## 범위

| 포함 | 제외 |
|---|---|
| 화면에서 경로 입력, 최근 목록, 작업 폴더 목록으로 프로젝트 열기 | 화면에서 초안 편집 |
| 설계 파일 유무에 따른 대조 모드와 분석 모드 | L3 이하 추정(타입, 에러, 계약, 함수) |
| Go 패키지와 import에서 모듈, 실행 단위, tier, 의존 추정 | 그룹 추정, 작은 패키지 병합 |
| L2 초안 YAML 생성과 `design/`에 쓰기(`daemok init`, 화면의 저장 버튼) | Go 외 언어 |
| 로컬 서버의 Host·Origin 검사 | 토큰 인증 |

그룹 추정은 완료 조건 3의 비교 결과와 두 번째 프로젝트의 사례를 보고 정합니다.

## 구성

| 위치 | 역할 |
|---|---|
| `internal/gosrc` (새) | 디렉토리의 Go 파일 선택과 파싱. `_test.go`와 `//go:build ignore` 파일 제외, OS·아키텍처 조건은 모두 참. `internal/codescan`의 `goFiles`, `ignored`, `satisfiable`과 `workspace.SkipDir`을 옮긴 것 |
| `internal/workspace` | 디스크가 아닌 설계 파일 내용으로 `Run`과 같은 대조를 하는 `RunSources` |
| `internal/infer` (새) | 코드 루트에서 초안 모델, 초안 YAML 텍스트, 분석 메모를 만듭니다. 파일을 쓰지 않습니다 |
| `internal/infer`의 쓰기 함수 | `design/`이 없거나 `*.yaml`이 없을 때만 `design/<system>.yaml`을 새로 만듭니다 |
| `cmd/daemok/init.go` (새) | `daemok init [--root DIR] [--design DIR]` |
| `internal/serve` | 현재 프로젝트 전환, 모드 판정, 프로젝트 API, Host·Origin 검사 |
| `internal/serve/web` | 프로젝트 열기 패널, 분석 모드 배지, 초안 탭 |

codescan과 infer는 `internal/gosrc` 하나로 파일을 고릅니다. 둘이 다른 파일 집합을 읽으면 초안의 `depends_on`과 import 대조가 어긋납니다.

## 분석 규칙

초안을 쓴 직후 `daemok check`(설계 검사와 코드 대조)의 오류가 0이 되도록 아래 규칙을 정합니다. 경고와 정보는 남을 수 있습니다. 파싱할 수 없는 Go 파일의 오류와 순환 import의 "의존 순환" 오류는 코드에 있는 사실이라 남습니다.

### 수집

- 루트의 `go.mod`에서 모듈 경로를 읽습니다. 없으면 "Go 모듈이 아니다" 오류.
- 루트부터 내려가며 `workspace.SkipDir`이 거르는 디렉토리를 건너뜁니다.
- 하위 디렉토리에 `go.mod`가 있으면 별개 모듈이므로 그 아래를 빼고 분석 메모에 남깁니다.
- Go 파일이 하나 이상 남는 디렉토리가 패키지입니다.
- 내부 의존은 모듈 경로로 시작하는 import입니다.

### 모듈과 실행 단위

| 패키지 | 초안 노드 | ID | 관계 |
|---|---|---|---|
| `package main` | `executables` | 디렉토리 이름. 루트면 system ID | `composes`: 직접 import하는 모듈 |
| 그 밖 | `modules` | 디렉토리 이름의 snake_case | `depends_on`: 내부 import |

- snake_case 변환: 소문자나 숫자 뒤의 대문자 앞, 대문자 연속 뒤에 소문자가 오면 그 연속의 마지막 대문자 앞에 `_`를 넣고 전부 소문자(`certGen` → `cert_gen`, `HTTPServer` → `http_server`).
- ID 충돌: 부모 디렉토리 이름을 앞에 붙입니다(`api_util`). 그래도 겹치면 경로 요소를 하나씩 더 붙이고, 경로 전체로도 겹치면 디렉토리 순서대로 `_2`, `_3`을 붙입니다. 모듈과 실행 단위는 ID 이름공간이 달라 서로 충돌하지 않고, 각 종류 안에서 이 규칙을 씁니다.
- ID와 경로가 다르면 `path`를 적습니다.
- 모듈로 넣지 않고 분석 메모에 이유를 남기는 패키지: Go 식별자(`^[A-Za-z][A-Za-z0-9_]*$`)가 아닌 경로 요소가 있는 패키지(`foo-bar`), 루트 디렉토리의 main이 아닌 패키지. 이 패키지를 import하는 코드는 코드 대조에서 "관리하지 않는 패키지" 정보로 나옵니다.
- `_`로 시작하는 디렉토리는 Go 도구처럼 건너뜁니다.
- 실행 단위 ID가 소문자 snake_case(`^[a-z][a-z0-9]*(_[a-z0-9]+)*$`)가 아니면 넣지 않고 분석 메모에 남깁니다.
- system ID는 모듈 경로에서 `v2` 같은 버전 요소를 뺀 마지막 요소의 snake_case입니다. `-`와 `.`은 `_`로 바꿉니다.

### tier

- 층 = 내부 의존의 층 중 가장 큰 값 + 1. 의존이 없으면 0.
- `tiers`는 `tier0`부터 가장 높은 층까지.
- 모든 플랫폼의 파일을 합쳐 보므로 빌드 조건이 다른 파일 사이에서 순환 import가 생길 수 있습니다. 서로 import하는 패키지 묶음은 같은 tier에 두고, 묶음의 층은 묶음 밖 의존의 층 중 가장 큰 값 + 1입니다. `depends_on`은 코드대로 적고 분석 메모에 묶음을 보여 줍니다.

### summary

패키지 doc 주석의 첫 문장. 없으면 생략.

### 출력

- 순서: `version`, `go_module`, `system`, `executables`, `tiers`, `modules`.
- 모듈은 tier 순, 같은 tier 안에서 ID 순. `depends_on`과 `composes`는 ID 순.
- 노드 하나를 한 줄 플로우 맵으로 씁니다.
- 첫 두 줄은 주석입니다. `daemok init`이 만든 초안이라는 것과 tier 이름과 묶음은 사람이 정한다는 것.
- 같은 코드에서는 같은 바이트가 나옵니다.

### 분석 메모

| 항목 | 내용 |
|---|---|
| 개수 | 패키지, 모듈, 실행 단위 |
| 건너뛴 것 | 중첩 모듈, Go 식별자가 아닌 경로, 파싱에 실패한 파일과 이유 |
| 많이 쓰이는 패키지 | 내부 import 수(fan-in) 상위 5개. 판정 없이 순위만 |
| 순환 import | 서로 import하는 모듈 묶음 |
| L3 노드 후보 | 손으로 쓴 `var Err… = errors.New(…)`·`fmt.Errorf(…)` 묶음과, 같은 패키지에 선언된 exported string 기반 타입으로 쓴 상수 블록(exported 값 2개 이상). 설계 노드는 exported Go 이름과 문자열 enum을 만들어서 unexported 타입·값과 int 기반 enum(iota 등)은 넣지 않습니다(`init --l3`와 같은 기준). 초안에는 넣지 않고 `gen: false` 후보로 알립니다 |
| 외부 의존 | go.mod의 직접 require(`// indirect` 제외)마다 그 모듈을 import하는 모듈·실행 단위 |
| 쓰는 이름 | 모듈·실행 단위마다 같은 Go 모듈의 다른 모듈에서 `패키지.이름`으로 쓴 export 최상위 선언과 그 종류(함수, 인터페이스, 타입, 에러, 상수, 변수). import 이름은 별칭, 없으면 대상 패키지의 package 절 이름이고, 대상 패키지에 그 이름의 export 선언이 있을 때만 셉니다. `_test.go`와 빈 import는 넣지 않습니다. 메서드 호출은 패키지 이름으로 쓰지 않아 잡히지 않습니다 |
| 그룹 후보 | 루트가 아닌 같은 부모 디렉토리 아래 형제 모듈 3개 이상이 형제 밖 모듈을 하나 이상 공통으로 쓰는 묶음. 형제끼리의 의존은 그룹 예외 후보. 그룹은 핸들러 종류(L3)가 있어야 해서 초안 YAML에는 넣지 않습니다 |

고아 모듈 같은 판정은 초안 모델에 기존 `check`를 돌린 진단으로 보여 줍니다. infer는 판정을 따로 만들지 않습니다.

## 서버

### 현재 프로젝트

- `Server`의 설계 디렉토리와 코드 루트를 잠금 아래에서 바꿀 수 있게 합니다.
- 열기: 경로를 절대경로로 바꾸고 디렉토리인지, `design/*.yaml`이나 `go.mod`가 있는지 확인한 뒤 `root = 경로`, `design = 경로/design`으로 두고 서명을 초기화해 `Refresh`합니다. 확인에 실패하면 현재 프로젝트를 바꾸지 않습니다. SSE 구독자는 새 버전 번호를 받습니다.
- `daemok serve`의 `--design`, `--root`는 시작 프로젝트를 정합니다. 기본값은 지금과 같습니다.

### 모드

`Refresh`마다 정합니다.

| 조건 | 모드 | 상태 |
|---|---|---|
| 설계 디렉토리에 `*.yaml`이 있음 | `check` | 지금과 같음 |
| 없음 | `analyze` | infer의 초안 모델을 `toView`로 바꾼 모델, 초안 모델의 `check` 진단, 초안 YAML, 분석 메모 |
| 루트가 Go 모듈이 아님 | `none` | 이유. `fatal`은 참 |

상태 JSON에 `mode`를 더합니다.

### API

| 요청 | 동작 | 실패 |
|---|---|---|
| `GET /api/projects` | 현재 프로젝트, 같은 저장소의 worktree, 최근 목록, 작업 폴더 목록. worktree와 최근 항목은 브랜치, 모드(`check`, `analyze`), 지금 연 것인지를 함께 줍니다 | |
| `POST /api/open` `{"path": "..."}` | 위 열기 | 400과 이유 |
| `POST /api/init` | 분석 모드의 초안을 infer의 쓰기 함수로 저장 | 분석 모드가 아니거나 `design/`에 `*.yaml`이 있으면 409 |

- 경로가 `~`나 `~/`로 시작하면 홈 디렉토리로 바꿉니다.
- 같은 저장소의 worktree: 지금 연 루트에서 `git worktree list`로 읽습니다. 하나뿐이거나 git 저장소가 아니면 비어 있습니다.
- 최근 목록: `os.UserConfigDir()/daemok/recent.json`, 최근에 연 순서로 10개. 없는 경로는 목록에 표시만 하고 열지 않습니다. 테스트는 설정 디렉토리를 주입합니다.
- 작업 폴더: `daemok serve --workspace DIR`을 주면 DIR 아래 깊이 3까지에서 `go.mod`가 있는 디렉토리를 찾습니다. 건너뛰기는 `workspace.SkipDir`. 요청마다 다시 찾습니다.

## 보안

루프백 주소에서 들을 때:

| 대상 | 규칙 |
|---|---|
| 모든 요청 | `Host`의 호스트 부분이 `127.0.0.1` 같은 루프백 IP나 `localhost`가 아니면 403 |
| POST | `Origin`의 호스트가 `Host`와 다르거나 없으면 403. `Content-Type`이 `application/json`이 아니면 415 |
| 쓰기 | `design/` 생성과 파일 하나의 `O_EXCL` 생성뿐입니다. 덮어쓰기 없음 |

루프백이 아닌 `--addr`에서는 `open`과 `init`이 403이고, 시작할 때 경고를 출력합니다. Host·Origin 검사는 하지 않습니다.

같은 PC의 다른 프로세스는 이 검사로 막지 못합니다.

## 화면

### 헤더

- 지금 설계 경로를 표시하는 자리를 프로젝트 버튼으로 바꿉니다. 프로젝트 폴더 이름과 git 브랜치(`aibox-hub · main`)를 표시하고 전체 경로는 툴팁으로. 주 worktree가 아닌 worktree는 폴더 이름 대신 주 worktree의 폴더 이름을 씁니다.
- 분석 모드에서는 "분석 모드 · 설계 파일 없음" 배지. 같은 저장소의 다른 worktree에 설계가 있으면 배지 옆에 "설계 있음: <브랜치>" 링크를 두고, 누르면 그 worktree를 엽니다.

### 프로젝트 열기 패널

진단 서랍과 같은 오른쪽 서랍입니다.

- 경로 입력과 열기 버튼. 입력 칸의 예시는 지금 연 경로. 실패 이유는 입력 칸 아래.
- 같은 저장소(worktree가 둘 이상일 때), 최근 목록, 작업 폴더 목록(`--workspace`가 있을 때). 항목을 누르면 엽니다. 같은 저장소와 최근 항목에는 브랜치와 모드(설계 있음, 분석)를 적고, 지금 연 worktree는 "지금"으로 표시하고 누를 수 없습니다.
- 모드가 `none`이면 화면을 열 때 이 패널을 엽니다.

### 분석 모드

| 탭 | 내용 |
|---|---|
| 지도, 모듈 | 초안 모델 |
| 흐름, 요구사항 | 숨김 |
| 초안 (새) | 분석 메모, 초안 YAML(읽기 전용), "design/에 저장" 버튼, 같은 일을 하는 `daemok init --root <경로>` 명령 복사 |

- 저장에 성공하면 서버가 다시 읽고 SSE로 대조 모드 화면이 그려집니다. 만든 파일 경로를 짧은 알림으로 보여 줍니다.
- 409면 "design/에 이미 설계 파일이 있다"를 보여 줍니다.
- 진단 서랍은 두 모드에서 같습니다.

## `daemok init`

| 결과 | 종료 코드 |
|---|---|
| 초안을 씀 | 0 |
| `design/`에 `*.yaml`이 있어 쓰지 않음 | 1 |
| Go 모듈이 아님, 쓰기 실패 | 2 |

`--design`의 기본값은 `<root>/design`입니다. 쓴 파일 경로와 분석 메모를 출력합니다.

## 테스트

| 대상 | 확인 |
|---|---|
| `internal/gosrc` | 옮긴 뒤 기존 codescan 테스트가 바뀌지 않고 통과 |
| infer 규칙 | `testdata`의 작은 Go 모듈로 층 계산, ID 충돌, snake_case, Go 식별자가 아닌 경로, 중첩 `go.mod`, 루트 main, `ignore` 파일, `_test.go` 제외, doc 주석 summary |
| infer 출력 | 두 번 실행한 결과가 같은 바이트. 초안을 다시 읽은 모델이 초안 모델과 같음 |
| 불변식 | infer fixture와 설계를 뺀 `codescan/testdata/scan`마다 초안을 `workspace.RunSources`로 대조해 파싱 실패 파일의 오류 말고는 오류 0 |
| `daemok init` | 위 표의 종료 코드 |
| serve | 열기 후 `mode`와 경로, Host·Origin 403, 루프백이 아닌 주소에서 `open`·`init` 꺼짐, `init`의 409, 최근 목록 저장, 작업 폴더의 깊이 제한과 건너뛰기, `~` 경로, 임시 저장소의 worktree 목록과 브랜치·모드·지금 표시 |
| `gitbase` | worktree 목록의 경로·브랜치, detached, 저장소 밖 |
| 화면 | headless 브라우저 캡처로 완료 조건 4, 5 확인. e2e `worktree.mjs`로 분석 모드 머리 링크 전환과 서랍의 같은 저장소 목록 |
