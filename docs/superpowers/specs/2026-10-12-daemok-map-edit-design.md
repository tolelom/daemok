# 화면에서 L2 편집

> [MVP 설계](2026-09-27-daemok-mvp-design.md)에서 제외한 "그림에서 편집"을 L2 모듈에 한해 넣습니다. 설계 파일이 원본이라는 원칙은 그대로이고, 화면은 설계 파일의 해당 부분만 고쳐 씁니다. 승인은 사용자의 커밋입니다.

## 범위

| 포함 | 제외 |
|---|---|
| 모듈의 tier 바꾸기 | 그룹·멤버·L3 이하 편집 |
| 모듈의 `depends_on` 대상 추가와 삭제 | 모듈 ID 바꾸기, 모듈 삭제 |
| 모듈 추가(ID와 tier) | 화면에서 YAML 직접 편집 |

## 고치는 방식

파일 전체를 다시 쓰지 않습니다. 파서가 남긴 노드 시작 위치에서 원본 텍스트를 읽어 해당 토큰이나 줄만 바꿉니다. 주석, 정렬, 다른 노드의 형식은 그대로입니다.

| 작업 | 플로우 맵 `id: { ... }` | 블록 맵 |
|---|---|---|
| tier | `tier:` 값의 식별자를 바꿈 | 같음 |
| 의존 추가 | `depends_on: [..]`이 있으면 `]` 앞에 `, X`. 없으면 `}` 앞에 `, depends_on: [X]` | 플로우 목록이면 같음. 블록 목록이면 마지막 항목 아래 같은 들여쓰기로 `- X`. 없으면 모듈 블록 끝에 `depends_on: [X]` 줄 |
| 의존 삭제 | 항목과 인접한 쉼표를 지움. 비면 `[]` | 블록 목록이면 그 줄을 지움 |
| 모듈 추가 | `modules:` 블록의 마지막 모듈 아래 `  X: { tier: T }` | 같음 |

`modules:`가 플로우 맵이거나 위치를 찾지 못하면 고치지 않고 이유를 돌려줍니다.

## 안전장치

- 고친 텍스트와 나머지 설계 파일을 `model.LoadSources`로 읽어 읽기 오류가 생기면 쓰지 않습니다(422). 설계 검사 오류(상위 tier 의존 등)는 막지 않고 진단으로 보여 줍니다.
- 요청은 화면이 그린 상태의 `version`을 함께 보냅니다. 서버가 감시로 다시 읽은 뒤의 버전과 다르면 쓰지 않습니다(409). 그사이 에디터에서 파일을 고친 경우입니다.
- 쓰기는 같은 디렉토리의 임시 파일에 쓴 뒤 이름을 바꿉니다.
- 루프백에서 띄운 대조 모드에서만 됩니다. Host·Origin 검사는 다른 POST와 같습니다.

## API

`POST /api/edit` `{"op": "tier" | "add_dep" | "remove_dep" | "add_module", "id": 모듈, "value": tier나 대상, "version": 상태 버전}` → 200 `{"version": 새 버전}`, 400(잘못된 요청), 403, 409, 422.

상태 JSON에 `canEdit`(루프백이고 대조 모드)을 더합니다.

## 화면

- 모듈 탭의 모듈: tier는 고르는 칸, `depends_on`은 대상마다 지우기 버튼과 추가 칸.
- 지도 오른쪽 칸: 모듈 추가(ID, tier).
- 실패하면 이유를 알림으로 보여 줍니다.

## 테스트

| 대상 | 확인 |
|---|---|
| 텍스트 고치기 | 플로우·블록 형식마다 네 작업, 주석과 다른 줄이 그대로인지, 찾지 못할 때 오류 |
| 서버 | 성공 후 상태 반영, 버전 불일치 409, 읽기 오류가 생기는 편집 422, 대조 모드가 아니면 403 |
| 화면 | headless로 tier 바꾸기, 의존 추가·삭제, 모듈 추가 |
