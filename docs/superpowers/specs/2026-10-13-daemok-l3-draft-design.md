# daemok L3 초안

> 설계가 있는 저장소에서, 설계 모듈 패키지에 손으로 쓴 선언 중 설계에 없는 것을 `gen: false` L3 노드 초안으로 만듭니다. `daemok init`의 L2 초안 다음 단계이고, coverage가 비율로 보여 주는 빈틈을 채우는 데 씁니다.

## 대상

| 항목 | 규칙 |
|---|---|
| 패키지 | 설계 모듈과 그룹 멤버의 디렉토리. 그 밖의 패키지는 보지 않습니다 |
| 파일 | 테스트가 아니고 생성 헤더가 없는 Go 파일 |
| 선언 | exported 최상위 선언 중 coverage가 설계 대응으로 세지 않는 것 |

## 종류

| 설계 노드 | 코드 | 노드 |
|---|---|---|
| `errors` | `var ErrX = errors.New("문자열")` | ID는 Go 이름, `message`는 문자열 |
| `consts` | 정수 리터럴, 문자열 리터럴, `N * time.Unit`(Millisecond, Second, Minute, Hour) | `type`과 `value` |
| `enums` | `type T string`과 `T` 타입 문자열 리터럴 상수 2개 이상 | `values`는 리터럴, 상수 이름이 `접두사 + GoName(값)`이 아니면 옮기지 않습니다 |
| `types` | struct | 필드를 모두 설계 문법으로 옮길 수 있을 때만 |

- 모든 노드는 `gen: false`와 `in: <모듈 또는 멤버>`를 가집니다.
- ID는 Go 이름을 snake_case로 바꾼 것입니다(에러는 Go 이름 그대로). `GoName(ID)`가 Go 이름과 다르면 `go.name`(enum은 `go.type`)을 붙이고, enum 접두사가 타입 이름과 다르면 `go.prefix`를 붙입니다.
- 위 형태가 아닌 선언과 함수는 옮기지 않고 이유와 함께 알립니다.

## 검증

초안을 설계 디렉토리의 파일 하나로 보고 기존 설계와 합쳐 검사, 생성 파일 대조, 코드 대조를 돌립니다. 초안 파일 안을 가리키는 오류나 경고가 나온 노드는 빼고 다시 돌립니다. 남은 초안은 설계에 그대로 더해도 새 오류와 경고를 내지 않습니다. 뺀 노드는 진단 메시지를 이유로 알립니다.

설계 검사에 이미 오류가 있으면 초안을 만들지 않습니다.

## 출력

| 경로 | 내용 |
|---|---|
| `daemok init --l3` | stdout에 YAML, stderr에 옮기지 않은 선언. 설계 디렉토리에 쓰지 않습니다. `daemok init --l3 > design/l3.yaml`처럼 새 설계 파일로 저장할 수 있습니다 |
| MCP `draft` 도구 | 인자 `l3: true`면 같은 YAML과 옮기지 않은 선언을 줍니다 |

YAML은 최상위 키(`errors`, `consts`, `enums`, `types`)마다 노드 하나를 한 줄 플로우 맵으로 쓰고, 노드는 모듈, ID 순입니다.

## 테스트

| 대상 | 확인 |
|---|---|
| 종류마다 | 코드 선언에서 기대한 노드 한 줄 |
| 이름 | snake_case 변환, `go.name`·`go.type`·`go.prefix`가 필요한 경우 |
| 대상 밖 | 설계에 이미 있는 선언, unexported, 모듈 밖 패키지, 생성 파일, 테스트 파일 |
| 검증 | 초안을 합친 설계가 새 오류·경고 없이 통과, 실패하는 노드는 빠지고 이유가 남음 |
| 명령 | `init --l3` 출력을 설계 파일로 저장하면 `check` 통과, coverage 비율이 오름 |
