# 미결과 남은 작업

> 2026-10-12 기준으로 정하지 않았거나 확인하지 못한 것입니다. 해결하면 이 문서에서 지우고 결과는 해당 설계 문서나 스펙에 적습니다.

## 정해야 할 것

| 항목 | 지금 | 선택지와 영향 |
|---|---|---|
| 그룹 `kind`를 선택 필드로 할지 | 그룹은 L3 핸들러 종류(`kind`)가 필수입니다. 그래서 `daemok init` 초안에는 그룹을 넣지 못하고, 분석 메모의 "그룹 후보"로만 제안합니다 | 선택으로 바꾸면 초안이 그룹까지 만들 수 있습니다. 대신 `kind` 없는 그룹은 등록 파일을 만들지 않는다는 규칙을 [모델](01-model.md)에 더해야 합니다. 형식이 바뀌는 결정이라 사용자가 정합니다 |
| 최종 지도 화면의 형태 | `daemok serve`의 로컬 웹 페이지가 임시 확인 수단입니다 | 웹 페이지로 갈지 프로그램 안의 화면으로 갈지 정하지 않았습니다. 어느 쪽이든 `/api/state` JSON을 그립니다 |

## 확인하지 못한 것

| 항목 | 이유 | 확인 방법 |
|---|---|---|
| `daemok mcp`를 실제 클라이언트에서 쓰기 | 클라이언트 설정을 바꿔야 해서 하지 않았습니다. 프로토콜 테스트와 표준 입출력 실행만 확인했습니다 | README "AI 연동" 절대로 등록한 뒤 `design`, `check`, `draft` 도구를 불러 봅니다 |
| 상태 만들기 직렬화의 효과 | 늦게 끝난 옛 상태가 새 버전으로 나가는 경쟁을 잠금으로 막았습니다. 다만 옛 코드에서도 재현하는 테스트를 만들지 못했습니다 | 재현 사례가 나오면 테스트로 고정합니다 |

## 미룬 작업

| 항목 | 미룬 이유 | 시작 조건 |
|---|---|---|
| TypeScript 생성(`ts_out`, `export: [ts]`) | 지금은 읽고 검사만 합니다. 도입 대상인 tolchain에 TS가 없습니다 | TS를 쓰는 대상 프로젝트가 생길 때 |
| 화면 편집 범위 넓히기(그룹·멤버, L3 이하, 모듈 ID 바꾸기와 삭제) | [화면 편집 스펙](../superpowers/specs/2026-10-12-daemok-map-edit-design.md)이 L2의 tier, 의존, 모듈 추가로 범위를 정했습니다 | L2 편집을 실제로 쓴 뒤 필요한 작업이 확인될 때 |
| 화면 편집 e2e를 CI에서 돌리기 | 브라우저와 node가 필요합니다. 지금은 `DAEMOK_E2E=1 go test ./internal/serve -run TestUIEditE2E`로 직접 돌립니다 | CI 실행기에 브라우저를 둘 수 있을 때 |
| MCP 쓰기 도구 | AI가 사용자 모르게 설계 파일을 고치지 못하게 도구를 모두 읽기 전용으로 두었습니다 | 쓰기 전에 사용자 확인을 받는 방식이 정해질 때 |
| 분석 병렬화 | 1000패키지 분석이 1.63초/회이고 96%가 파일 열기입니다. 실제 대상(25패키지)은 수십 ms입니다 | 큰 저장소에서 느리다는 사례가 나올 때 |
