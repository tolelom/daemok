# 미결과 남은 작업

> 2026-10-14 기준으로 정하지 않았거나 확인하지 못한 것입니다. 해결하면 이 문서에서 지우고 결과는 해당 설계 문서나 스펙에 적습니다.

## 미룬 작업

| 항목 | 미룬 이유 | 시작 조건 |
|---|---|---|
| 화면 편집 범위 넓히기(멤버, L3 이하, 그룹 추가·삭제, 모듈 ID 바꾸기) | [화면 편집 스펙](../superpowers/specs/2026-10-12-daemok-map-edit-design.md)이 모듈·그룹의 tier와 의존, 모듈 추가·삭제로 범위를 정했습니다 | L2 편집을 실제로 쓴 뒤 필요한 작업이 확인될 때 |
| 화면 편집 e2e를 CI에서 돌리기 | 브라우저와 node가 필요합니다. 지금은 `DAEMOK_E2E=1 go test ./internal/serve -run TestUI`로 직접 돌립니다(편집, 지도, L3 초안, 생성) | CI 실행기에 브라우저를 둘 수 있을 때 |
| VS Code 패널 | 지금은 브라우저 탭으로 씁니다. 패널은 같은 웹 페이지를 감싸는 방식으로 더하고, 웹뷰 안에서 루프백 검사가 그대로 동작하는지는 확인하지 않았습니다 | 브라우저와 에디터를 오가는 불편이 실제로 생길 때 |
| L0 외부 경계 생성 | 무엇을 생성할지 정하지 않았고 tolchain에 필요한 사례가 없습니다. 지금은 검사만 합니다 | 외부 경계 코드를 생성해야 하는 구체 사례가 생길 때 |
| 포인터가 아닌 `omitempty` 필드의 TS 생성 | `optional`은 포인터와 `omitempty`를 함께 뜻해 `string,omitempty` 같은 값 타입 필드를 설계로 적을 수 없습니다. 그런 필드가 있는 손으로 쓴 타입은 코드 대조가 태그 차이로 막아 `export: [ts]`를 붙일 수 없습니다. fiber_api_server에서는 `ErrorResponse.Message` 하나입니다 | 이런 타입을 TS로 내보내야 하는 사례가 생길 때 |
| 분석 병렬화 | 1000패키지 분석이 1.63초/회이고 96%가 파일 열기입니다. 실제 대상(25패키지)은 수십 ms입니다 | 큰 저장소에서 느리다는 사례가 나올 때 |
| 마지막 모듈 삭제 뒤 다시 추가 | 모듈이 하나뿐인 `modules:`에서 지우면 블록이 비어 `add_module`이 블록 형식을 찾지 못해 거부합니다. 지운 모듈 위 설명 주석도 남습니다 | 모듈을 모두 지웠다가 다시 쓰는 사례가 생길 때 |
| 화면 편집과 MCP edit 사이 잠금 | 두 프로세스가 같은 파일을 고치면 읽기와 이름 바꾸기 사이 수 ms 동안 한쪽 변경이 사라질 수 있습니다. 409 검사는 자기 프로세스의 버전만 봅니다 | 두 경로를 동시에 쓰는 사례가 생길 때 |
| git 2.31 미만 지원 | 새 worktree 저장이 `rev-parse --path-format=absolute`를 씁니다 | 오래된 git 환경에서 쓸 일이 생길 때 |
| L3 초안 검증 상한 | 한 노드 안에서 같은 snake ID로 바뀌는 필드(`URL`, `Url`)는 YAML 중복 키 오류 하나만 내 라운드마다 노드를 하나씩 뺍니다. 그런 노드가 20개를 넘으면 초안 전체가 실패합니다 | 실제 저장소에서 상한에 걸릴 때 |
| TS 정수 2^53 초과 | `9007199254740993` 같은 상수와 uint64·int64 필드가 TS number에서 정밀도를 잃습니다 | 큰 정수를 TS로 내보내는 사례가 생길 때 |
| 선택 map 필드의 TS `\| null` | 선택 슬라이스·bytes는 `\| null`을 떼지만 선택 map은 남깁니다. Go 쪽 선택 map이 null을 낼 수 있는지에 따라 맞출 쪽이 갈립니다 | 선택 map을 TS로 내보내는 사례가 생길 때 |
| 일반 함수 스펙 예제의 큰 정수 | 예제 `given: { a: 18446744073709551615 }`가 int 범위를 넘어 케이스 테스트에 문자열로 들어갑니다 | 케이스 값에 큰 정수가 필요할 때 |

## 결정 대기

| 항목 | 내용 |
|---|---|
| 심볼릭 링크 설계 파일의 편집 | 화면 편집 스펙은 설계 파일이 심볼릭 링크면 가리키는 파일을 바꾼다고 정했습니다. MCP edit도 같은 `edit.Apply`를 써서, 링크가 설계 디렉토리 밖을 가리키면 그 파일을 고칩니다. 대상에 해당 모듈 블록이 있어야 하고, edit 도구는 쓰기 도구 힌트(`destructiveHint`)를 내지만 실제 확인 여부는 MCP 클라이언트 설정에 달려 있습니다. 링크 대상이 설계 디렉토리 밖이면 거부할지 정해야 합니다 |
