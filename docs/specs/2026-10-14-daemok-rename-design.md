# 설계 ID 이름 바꾸기

> 설계 노드 하나의 ID를 바꾸고, 그 ID를 가리키는 모든 참조를 설계 파일 전체에서 함께 바꿉니다. 기본 동작은 코드 이름을 그대로 둡니다.

## 목적

구조를 바꾼 뒤에도 다른 곳이 옛 이름을 참조하는 문제를 없앱니다([개요](../design/00-overview.md) 「문제」). 설계를 고치는 비용을 코드만 고치는 비용보다 낮춘다는 원칙 6을 이름 바꾸기에도 적용합니다. 지금은 ID 하나를 바꾸려면 여러 설계 파일의 정의와 참조, 타입 문자열 안의 ID를 손으로 찾아 고쳐야 합니다.

## 동작

| 모드 | 설계 | 코드 |
|---|---|---|
| 기본 | 정의와 모든 참조를 새 ID로 바꾸고, 코드 이름을 옛 값으로 고정하는 키를 노드에 더함 | 바뀌지 않음. 생성 파일이 패키지 디렉토리와 내용으로 같음 |
| `--code` | 정의와 모든 참조를 새 ID로 바꿈. 고정 키는 더하지 않음 | 생성 코드 이름이 새 ID를 따름. 손으로 쓴 참조는 컴파일 오류로 드러남 |

이미 코드 이름 키(`go.name`, `go.type`, `path`)가 있는 노드는 두 모드 모두 그 키를 건드리지 않습니다. 코드 이름이 ID에서 나오지 않으므로 이름 바꾸기가 코드에 영향을 주지 않습니다.

`gen: false` 노드는 `--code`여도 고정 키를 더합니다. 손으로 쓴 선언이라 daemok이 코드 이름을 바꿀 수 없기 때문입니다. 결과에 이 사실을 알립니다.

## 종류별 고정 방법

| 분류 | 종류 | 기본 모드의 고정 |
|---|---|---|
| 코드와 무관 | tier, 요구사항, 액터, 외부 인터페이스 | 필요 없음 |
| `go.name` | 타입, 계약, 핸들러 종류, 함수, 에러, 상수 | `go: { name: <옛 Go 이름> }` |
| `go.type` | enum | `go: { type: <옛 Go 타입 이름> }`. 접두사 기본값이 타입 이름이므로 값 상수 이름도 유지됨 |
| `path` | 모듈, 그룹 | `path: <옛 경로>`. 경로 키가 없으면 ID가 경로이기 때문 |
| 고정 불가 | 이벤트, 이벤트 종류, 흐름, 실행 단위, 그룹 멤버 | 형식에 코드 이름 키가 없음. `--code` 없이는 거부 |

에러는 `go.name`이 없으면 ID가 Go 이름이므로 고정 값은 옛 ID입니다. 그 밖의 `go.name` 종류는 옛 ID의 Go 이름 변환(`model.GoName`) 결과입니다.

함수의 `go.name`은 일반 함수에만 쓸 수 있어 핸들러 함수와 계약 함수에는 고정 키를 더하지 않습니다. 핸들러 함수 이름과 케이스 테스트 이름은 함수 ID에서 나오므로, 생성 코드가 달라지면 기본 모드는 거부하고 `--code`를 안내합니다.

enum과 핸들러 종류의 생성 파일 이름은 ID에서 나옵니다(`core/status.gen.go`). 고정 키를 더해도 파일 이름은 바뀌지만 패키지와 선언은 그대로라 기본 모드에서 받고, 바뀌는 파일 이름을 결과에 알립니다. 옛 파일은 `daemok gen`이 지우고 새 파일을 씁니다.

고정 불가 종류를 `--code`로 바꾸면 실행 단위와 그룹 멤버는 디렉토리가 바뀝니다(`cmd/<ID>`, `<그룹 경로>/<멤버 ID>`). 손으로 쓴 파일이 있는 디렉토리는 daemok이 옮기지 않으므로, 결과에 옮길 디렉토리를 알립니다. `path` 키가 없는 모듈과 그룹도 `--code`면 경로가 새 ID가 되어 같이 알립니다.

## 참조 찾기와 바꾸기

- 바꾸는 자리는 모델이 읽은 위치에서 얻습니다. 노드 정의의 키 위치와 모든 참조(`Ref`)의 위치가 대상입니다. 위치에는 파일, 줄, 열이 있어 같은 글자의 다른 의미(enum 값, summary 문장)를 건드리지 않습니다.
- 이벤트 종류의 key enum 값은 이벤트 ID여야 하므로, 이벤트를 바꾸면 그 enum의 같은 값도 함께 바꿉니다.
- 타입 문자열(필드, 파라미터, 반환, 이벤트 data의 `"[]*post"`, `"map[kind]post"`)은 문자열 안의 ID 토큰을 찾아 바꿉니다. 토큰 경계는 `[`, `]`, `*`, `,`와 문자열 끝이고, 따옴표로 감싼 값은 따옴표 다음부터 셉니다.
- 같은 ID를 여러 종류가 쓸 수 있으므로(모듈 `post`와 타입 `post`) 종류를 함께 받습니다. 참조도 그 종류를 가리키는 자리만 바꿉니다. 모듈·그룹·멤버와 enum·타입은 서로 이름이 겹칠 수 없는 묶음이라, 이 묶음을 함께 가리키는 참조(`depends_on`, 타입 문자열)는 바꾸는 노드의 ID와 같은 자리를 바꿉니다.
- 바꿀 자리를 모두 모은 뒤 파일마다 뒤에서부터 바꿉니다. 앞의 교체가 뒤 위치를 밀지 않습니다.
- 고정 키는 노드 서식을 따라 더합니다. 흐름 형식(`{ ... }`)이면 닫는 괄호 앞에, 블록 형식이면 노드의 마지막 줄 뒤에 같은 들여쓰기로 넣습니다. 노드에 `go:` 맵이 이미 있으면 그 안에 `name`이나 `type`을 더합니다.

## 거부 조건

다음이면 아무 파일도 쓰지 않고 이유를 알립니다.

- 해당 종류에 옛 ID가 없음
- 새 ID가 그 종류의 ID 규칙에 맞지 않음, 또는 같은 종류에 이미 있음. 모듈·그룹·멤버와 enum·타입은 묶음 전체에서 봄
- 고정 불가 종류인데 `--code`가 없음
- 새 ID가 YAML이 문자열이 아닌 값으로 읽는 이름(`null`, `true`, `false` 등)임. 참조 자리에서 빈 값이 되어 검사가 잡지 못함
- 생성 파일 이름을 ID로 짓는 종류(enum, 핸들러 종류, 이벤트 종류, 흐름)의 새 ID가 Go 빌드 제약 접미사(`_windows`, `_arm64` 등)로 끝남
- 바꾼 결과가 편집 전에 없던 읽기 오류를 냄
- 바꾼 결과의 설계 검사 진단이 바꾸기 전보다 늘어남. 비교는 진단 메시지에서 옛 ID를 새 ID로 바꾼 뒤 수를 세어 합니다
- 기본 모드에서 바꾼 결과의 생성 파일이 패키지 디렉토리와 내용으로 바꾸기 전과 다름
- 기본 모드인데 바꾸기 전 설계에 검사 오류가 있어 생성 코드를 비교할 수 없음
- 기본 모드에서 TS 생성 결과가 달라짐. TS 이름은 ID에서 나오고, `ts_out` 디렉토리가 없어도 비교함

쓰기는 기존 `edit`과 같이 파일마다 임시 파일에 쓴 뒤 이름을 바꿉니다. 여러 파일을 고칠 때 중간에 실패하면 이미 바꾼 파일을 원래 내용으로 되돌립니다.

## 진입점

| 진입점 | 형태 |
|---|---|
| CLI | `daemok rename <종류> <옛 ID> <새 ID> [--code] [--design <디렉토리>] [--root <코드 루트>]`. 바꾼 파일, 더한 고정 키, 옮길 디렉토리를 출력 |
| MCP | `edit` 도구에 `rename` 작업. 인자 `kind`, `id`(옛 ID), `value`(새 ID), `code`(불리언). 기존 `edit`과 같이 `--allow-write`일 때만 있고, 설계 디렉토리 밖을 가리키는 심볼릭 링크 파일이 대상에 있으면 거부 |

종류 이름은 설계 파일의 키를 씁니다: `requirements`, `executables`, `tiers`, `modules`, `groups`, `members`, `enums`, `consts`, `errors`, `types`, `contracts`, `handler_kinds`, `event_kinds`, `events`, `funcs`, `flows`, 그리고 `system` 아래의 `actors`, `interfaces`. 멤버 ID는 설계 전체에서 유일하므로 그룹 없이 씁니다.

## 테스트

- 종류마다 기본 모드로 바꾼 뒤 생성 파일이 패키지 디렉토리와 내용으로 같고 진단 수가 같음. 테스트 설계는 `internal/gen/golang/testdata/basic`을 씀
- 타입 문자열 안의 ID, 여러 파일에 걸친 참조, 같은 ID의 다른 종류가 있을 때 해당 종류만 바뀜
- enum 값이나 summary에 같은 글자가 있어도 바뀌지 않음
- 흐름 형식과 블록 형식 노드, `go:` 맵이 이미 있는 노드에 고정 키 더하기
- `--code`에서 생성 코드 이름이 새 ID를 따르고, `gen: false` 노드에는 고정 키가 더해짐
- 거부 조건마다 파일이 바뀌지 않음. 두 번째 파일 쓰기가 실패하면 첫 파일이 원래 내용으로 돌아옴
- tolchain과 fiber_api_server 설계(클론이 있을 때)에서 종류마다 하나씩 바꿔 생성 결과와 진단이 같음

## 하지 않는 것

- 손으로 쓴 Go 코드의 참조 바꾸기. Go 표준 라이브러리만 쓴다는 원칙과 맞지 않고, 컴파일러가 남은 참조를 알립니다
- 디렉토리 옮기기
- 화면에서 이름 바꾸기. 화면 편집 범위를 넓히는 일이라 미룬 작업에 둡니다
- 이벤트, 흐름, 실행 단위, 그룹 멤버에 코드 이름 키를 더하는 형식 확장
